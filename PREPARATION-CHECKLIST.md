# Student Preparation Checklist

**Project:** Group Expense Splitter  
**Goal:** Build a working application by solving a real-world problem using HTML, CSS, and JavaScript.

You do not need to know everything before joining. Use this checklist to get ready to learn and build with confidence. For beginner-friendly explanations and examples, work through the [HTML, CSS and JavaScript Preparation Topics Guide](PREPARATION-TOPICS-GUIDE.md). The section numbers below point to that guide.

## 1. Accounts and access

- [ ] I can sign in to my own GitHub account.
- [ ] I have submitted my correct GitHub username through the registration form.
- [ ] I can join Google Meet using my Google account.
- [ ] I have accepted the GitHub repository invitation from my email, if one was sent.
- [ ] I can open my individual project repository (`expense-splitter-<my-github-username>`) on GitHub.

## 2. Laptop and development setup

- [ ] I have access to a laptop or desktop.
- [ ] I have a reliable internet connection.
- [ ] I have tested my audio and microphone for Google Meet.
- [ ] I know how to share my screen during a meeting.
- [ ] I can open the browser DevTools Console and run `2 + 3` (guide section 0.1).

**Once my repository has been shared with me:**

- [ ] I can create or open a GitHub Codespace for my repository (**Code → Codespaces → Create codespace on main**).
- [ ] In the Codespaces terminal, I can run `npm run dev` and open the preview on port `5173`.
- [ ] I can run a file with `node` in a second terminal, for example `node warmups/practice.js` (guide section 0.2).
- [ ] I have made one test commit, pushed it, and can see it on GitHub (guide section 5).
- [ ] I know how to stop my codespace at the end of the day so it does not use up my free hours.

You do not need to install additional software unless the trainer asks you to. See the [GitHub Codespaces quickstart](https://docs.github.com/en/codespaces/quickstart) for help. If setup fails, contact the trainer before the first session rather than spending hours stuck alone.

## 3. HTML, CSS and JavaScript revision

You do not need to master every topic before the bootcamp. Just revise the basics and try the examples.

**Needed from Day 1**

- [ ] Variables: `let` and `const` (3.1)
- [ ] Data types: strings, numbers, booleans, `undefined` and `null` (3.1)
- [ ] Arithmetic, and why we store money as whole paise (3.2)
- [ ] Comparisons `===` and `!==`, and logical operators `&&`, `||` and `!` (3.3)
- [ ] Conditions: `if`, `else if`, and `else` (3.4)
- [ ] Functions, parameters, and return values, including returning a list of error messages (3.5)
- [ ] Arrays: indexes, `length`, `push`, and `includes` (3.6)
- [ ] Objects: dot notation and bracket notation, and why we use IDs instead of names (3.7)
- [ ] Loops: `for`, `for...of`, `while`, and `for...in` (3.8)
- [ ] Basic array methods: `map`, `filter`, and `find` (3.9)
- [ ] Why `logic.js` uses `export`, and what `import` does (3.10)
- [ ] Reading an error message and finding the line it points to (0.3)

**Needed from Day 3** (a quick read is enough for now)

- [ ] HTML forms, a dropdown, checkboxes, lists and tables (1.2–1.4)
- [ ] CSS selectors, the box model, and Flexbox (2.1–2.4)
- [ ] Responding to a form `submit` with `event.preventDefault()` (4.1)
- [ ] Showing a list with `createElement`, `textContent` and `appendChild` (4.2)

**Preview — read once, no need to master** (3.11)

- [ ] `Math.floor` and the remainder operator `%`
- [ ] Sorting numbers with a compare function
- [ ] Why changing an object inside a function changes the original

## 4. Think about the problem

Imagine three friends—Asha, Ravi, and Mina—share a hotel bill of ₹900. Asha pays the entire amount.

- [ ] I can explain how much each person should contribute.
- [ ] I can explain who owes money and who should receive money.
- [ ] I can think of how to represent people and expenses in JavaScript.
- [ ] I can identify questions we need to answer before building the application.

**Challenge question:** What changes if one person does not participate in an expense, or if different people pay for different expenses?

You do not need to solve every case now. Come prepared to discuss your approach.

## 5. Bootcamp commitment

- [ ] I have blocked the morning, afternoon, and evening sessions on my calendar.
- [ ] I will join sessions on time and participate actively.
- [ ] I am willing to write the steps in plain English before writing code.
- [ ] I will attempt problems before looking at a solution.
- [ ] I will ask questions when I get stuck.
- [ ] I will test my code and investigate errors rather than immediately giving up.
- [ ] I will make sure I understand and can explain the code I submit.
- [ ] I have read [How we will use AI](README.md#how-we-will-use-ai) in the README, and I will use AI as a learning assistant, not as a replacement for my own thinking.

## 6. Final readiness check

Before the first session, confirm the following:

- [ ] My accounts and development environment are ready.
- [ ] I have pushed at least one commit to my repository.
- [ ] I have revised the basic JavaScript concepts.
- [ ] I understand the problem we are going to solve.
- [ ] I am ready to attend the sessions and practise between them.
- [ ] I know where to ask for help if I face a setup issue.

## Remember

You are not expected to arrive as an expert programmer. The goal is to learn how to break down a real problem, design a solution, implement it, test it, debug it, and explain why it works.

**Come curious. Think independently. Build together.**
